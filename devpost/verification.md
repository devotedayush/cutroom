## Privacy implementation audit

This is a static review of the current application source, its runtime imports, installed Mediabunny source, and generated production assets. It supports the implemented local processing design; it is not a blanket security guarantee or a completed live network capture.

- **Media input:** `src/media/import.ts > importMedia` receives browser-selected `File` objects. Video decoding uses `new BlobSource(file)`; image decoding uses `createImageBitmap(file)`. Thumbnails are generated on a canvas as data URLs. There is no URL-based remote media source in application code.
- **Preview and export:** `src/App.tsx` feeds local `blob:` URLs to media elements. `src/media/export.ts > exportProject` decodes `asset.file` with `BlobSource`, renders through local canvas/WebCodecs/Web Audio, and writes to `BufferTarget`. `capTimeline` reads its in-memory encoded `Blob` and remuxes into another memory buffer. Downloads use a local object URL, not a server request.
- **Project files:** `src/storage.ts > serializeProject` writes project name, titles/edit decisions, and used-source metadata: filename, size, modification time, media kind, duration, and IDs. It excludes media bytes, thumbnail data, object URLs, and filesystem handles. A saved project therefore reveals source filenames and user-entered text to anyone the user shares that file with. Reopening reads the selected project using `File.text()` and asks for original files to relink; it does not fetch originals remotely.
- **Application requests and assets:** No application `fetch`, XMLHttpRequest, WebSocket, EventSource, beacon, file upload, telemetry, analytics client, or application console logging was found in `src/`. `index.html` uses same-origin application assets. CSS uses installed/system font families; icons come from bundled `lucide-react` SVG code. No remote font stylesheet, image, or CDN dependency was found. Loading the website still requests its HTML, JavaScript, CSS, icon, manifest, and service worker from its serving origin; a host can observe ordinary access metadata for those requests.
- **Dependency evidence:** The runtime graph imports React, React DOM, lucide-react, and Mediabunny from installed packages, bundled into the production JavaScript. Mediabunny's `BlobSource` implementation reads `Blob.slice(...).stream()` or `arrayBuffer()` locally (`node_modules/mediabunny/src/source.ts > BlobSource`). The dependency also offers a separate network-backed `UrlSource`, but application code does not instantiate it and the inspected production bundle did not contain that class name. The bundle's `fetch(o.href, ...)` was Vite's module-preload fallback for application asset links, not a media upload. Documentation/error URL strings in dependency code are not evidence of requests. React/Mediabunny retain ordinary local console error/warning diagnostics; no remote log sink was found.
- **Offline shell design:** `src/pwa.ts > registerOfflineShell` registers `/sw.js` only in production. `scripts/finalize-static.mjs` generates a versioned allowlist from build-output files; the service worker installs those app-shell resources and intercepts same-origin GET requests only. It does not add selected files, blob/data URLs, generated thumbnails, or project documents to Cache Storage. Navigation may fetch the app page if no cached shell is available. The generated CSP restricts connections to the serving origin; this is defense in depth, not proof that same-origin uploads are impossible. The generated `dist/sw.js` allowlist was also checked: `/`, `/index.html`, `/manifest.webmanifest`, `/icon.svg`, and the built JavaScript/CSS files only. A live service-worker cache/network inspection remains a separate browser check.
- **Retention and object URLs:** Editing state and imported `File` references are in React memory; no localStorage, IndexedDB, OPFS, or media persistence layer was found. Reload discards the active media/edit session unless the user saved a project and relinks originals. `importMedia` disposes its decoder and revokes its object URL on failure; `relinkAssets` revokes partial imports on failure; export closes bitmaps/disposes inputs; output preview URLs are revoked on replacement/unmount; `downloadBlob` revokes a download URL after 60 seconds. Active library URLs remain usable until workspace replacement/unmount. The audit identified incomplete cleanup for unused/replaced pending generated-demo URLs in `App.openProject`. The subsequent source fix was reviewed: unused generated URLs and failure paths are revoked; `clearPending` releases abandoned references when opening another project or canceling relink; unmount also releases pending media. Runtime heap/lifetime behavior was not measured.

### Privacy verification limits

No browser automation or runtime network capture was performed for this audit. A browser check should inspect network requests while importing, editing, previewing, saving/reopening, exporting, and reloading offline; inspect Cache Storage to confirm it contains the app shell only. The browser, its codecs, extensions, operating system, downloaded files/backups, and any hosting access logs are outside this application's control. Dependency review was targeted at the actual media paths and built bundle, not an exhaustive supply-chain audit. Future code or dependency changes can change these findings.

## Browser evidence — production build

Tested in current desktop Chrome on 27 October 2026 IST using synthetic, original fixtures only. A production preview was served locally, its app shell loaded, and tab-scoped Chrome network emulation was set offline. Reload succeeded; response events showed HTML, JavaScript, CSS, manifest and icon served by the service worker. Imported the A/B MP4 files and portrait PNG while offline.

Built a five-second 9:16 edit: B source2–4s muted, A source1–3s split into two contiguous one-second clips, then one-second portrait still. Added distinct titles, reordered, split, undid/redid, played through the sequence, canceled an export, and retried. Exported both formats while offline and downloaded them. Browser result players reported readyState4, no error, duration5,720×1280. FFprobe confirmed WebM VP8/Opus and MP4 H.264/AAC, both five-second containers. Extracted frames show the expected red→blue→still order, source-time labels and titles.

Decoded audio validation: first0.2–1.8s RMS0 (muted); second2.2–3.8s RMS≈0.0882 with dominant440Hz from A, negligible660Hz from B; still4.2–4.8s silence/codec noise≈0.0000042 or less. Native codecs may retain subframe/audio priming differences; no universal sample-perfect codec claim is made. FFmpeg8.0.1 emits an Opus packet-header warning on both a fresh libopus control file and test outputs; debug decode summaries report zero decode errors.

Raw trace and media evidence are kept only under ignored artifacts/qa. Trace included browser-extension resources and local blob/data media resources; those are not application uploads. Application-origin HTTP requests were GET requests for shipped app assets. No application media upload/request to an external HTTP destination was observed in this tested flow.

A project-reopening test found an asynchronous nested file picker did not open reliably. It was replaced by an explicit persistent relink dialog with a direct user button; re-verification is pending below. An update-cache race during repeated local builds was corrected by allowing new service workers to wait for existing editing tabs to close rather than forcing activation during a live edit.

Tab-scoped offline emulation was restored to online after testing. This does not assert that third-party browser extensions or operating-system components are private.

Project reopening re-verification passed in a fresh production session: explicit relink dialog listed all three original files; direct file selection restored the four clips,5s duration,9:16 ratio,titles,source trims and muted volume; undo/redo were cleared as intended.

Luna's independent browser pass found an empty page on a previously rebuilt local origin. The app-shell fetch handler was corrected to read its own versioned cache and ignore the static server's Vary:Origin header for known shipped assets. New workers wait for existing editing tabs to close. Fresh-origin and update verification is in progress; this issue is not counted as a passed check.

The learner explicitly requested localhost-only running. Hosted deployment is omitted. Public GitHub source publication was separately authorized.

Two service-worker regression checks pass: navigation must use the active version's shell even when another cache contains a different version, and known static app assets ignore Vary:Origin while media requests and writes remain outside the cache handler.
